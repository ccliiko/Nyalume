# 动作检查与共同经历：试玩版

重启 v2 的主 App 和 3D 桌宠后使用。无需新插件；动作检查需要本机 Node.js，当前工作区已具备解析器和素材。

## 动作检查

在主窗口左侧展开 **本对话记忆 / 状态**，点击 **检查当前模型动作库**。也可以在工作区模式对 Agent 说：“检查一下当前桌宠和动作库的兼容性。”

两个入口共用 `pet_check_motions()` → 桌宠本机 `/motion_check` → `tools/check_motion_compat.mjs`。检查当前模型与当前可选动作库，沿用动作筛选及每模型白名单，不切换动作、不自动改配置。最多检查 200 支，检查器超时 45 秒，主 App 等待上限 50 秒；同一时刻只运行一次。

表格分别显示非中立缺失骨骼、有效表情缺失及全部缺失骨骼数。名称最多展示 32 项，完整计数保留。没有有效轨道缺失，也需要实际试播检查比例、IK、物理和穿模。桌宠离线、空动作库、缺 Node.js、解析失败及超时会显示具体结果。

检查结束会记下“为哪个模型检查了几支动作、几支有缺失、几支解析失败”。这只证明检查发生过，不代表选舞约定自动完成。同一天相同模型与检查报告只保存一次；用户删除后重新主动检查，会产生一次新的经历。

## 试一条小约定

1. 对 Agent 说：“我们一起给桌宠选一支合适的舞吧。”它可用 `companion_journal(action="propose")` 保存草案。
2. 在 **共同经历** 卡片点 **好，就这么约定**；不想接就点 **先不约了**。也可直接在窗口输入约定并点 **记下我们的约定**。
3. 检查、试播并选好后，点 **我们完成了**。卡片转为“用户确认完成”的共同经历，并给一句短反馈。
4. 开启另一段 Nyalume 对话，问“我们最近一起做过什么？”系统会提供已确认约定和最近经历供它引用。
5. 点 **删除记录** 后，之后新生成的共同经历上下文不会再包含这条。过去的聊天原文、已有便签和摘要不随之改写。

日常模式只开放 `pet_plan` 照料虚拟小窝；其他工具仍关闭，窗口按钮可用。Nyalume 可以读取已确认的共同经历，标准助手不自动注入这段角色记忆。

## 回应卡片与持续的小窝故事

每轮回复下方提供三个带说明的方向，先选择，再点「发送这个回应」。也可以继续在输入框自由打字。
选项发送完整的用户回应，走普通聊天流程，不直接执行隐藏动作，也不清空尚未发送的输入草稿。
新回复替换上一轮的可选卡片；重新打开对话和分支对话都保留对应选项。

选项优先与正文来自同一次模型回复；程序隐藏并校验末尾的界面数据。
日常聊天漏给合法选项时，根据用户这轮输入和刚生成的回复补请求模型，最多两次、共享45秒预算。
标题与回应都由模型按当前情境生成，不再使用固定三句兜底；补生成不可用时保留自由输入。
日常对话默认采用小窝日常＋轻奇幻：她提出自己的小愿望，遇到一个小困难，用户可追问、参与或暂缓。
故事保存标题、目标、当轮虚拟情节、待续线索及暂停/完成状态，记录用户真实发来的回应。
多个窗口同时续写时，旧版本不能覆盖新进度。剧情记录明确标为虚拟故事，不当作现实文件或动作的执行凭据。
已保存的线索也会提供给主动搭话和便笺，不要求连续签到。工作话题不会被要求附带剧情。

用户明确说「选薄荷」「陪你准备花盆」「喜欢这个计划」「暂停小计划」时，Agent 可调用 `pet_plan` 保存。
工具按现有阶段和选项校验，不允许直接催熟、覆盖正在进行的计划，重复陪伴仍只算当前阶段一次。
剧情与共同经历随本地数据库备份，暂不加入跨设备剧情同步。

## 存储与范围

复用 `agent.db`，新增 `companion_entries` 表。记录创建/确认/完成时间、来源和状态，跨对话、跨日、重启保留，随数据库快照备份；本轮不加入云同步。列表每次取 50 条，可查看更早记录；给人格的上下文最多取三条进行中的约定及三条最近经历。

自动事实来源先接动作检查，第二类来源是用户明确确认的约定。记录、去重和状态推进不调用 LLM；Agent 发言及读取少量上下文仍有正常 token 消耗。离线不扣分，不新增主动打扰或连续签到要求。

这是可用的生活经历小闭环。旧 `world/` 的模板事件、自动日记摘要、下载完成触发、复杂剧情分支和骨骼养成反应尚未接入。

验证：全量 208 项测试通过，包含真实 PMX/VMD 的窗口与 Agent 双入口、离线/超时处理、跨日去重、约定确认及完成、数据库恢复、删除后的上下文移除，以及真实浏览器按钮流程。未调用云端模型验证台词表现，实际措辞仍取决于所用模型。
