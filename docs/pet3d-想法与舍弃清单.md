# 3D 桌宠：想法与舍弃清单

> 记录"想过但没做"和"做了又砍掉"的东西，免得以后有人（包括我自己）把砍掉的又加回来。
> 最后更新：2026-09-21

## 一、已经做了（保留）

- 真 3D：three.js MMDLoader 加载 .pmx，逐像素透明 + 点击穿透（分层窗口 + 每帧 PNG）
- 输入：全局鼠标钩子 + 原始位移积分（游戏锁光标时用）；**钩子永不吞输入**
- 互动：左键按部位戳（头/脸/胸/手/裙/披风/腿）、拖拽（抓头发/衣袖/裙摆带动局部）、
  双击下一支舞、右键拖旋转、滚轮缩放、中键退出
- 表情：部位随机反应池 + 状态表情 + 主动表情接口（`face`）
- 视线跟随：以**她自己轮廓**为参照（眼睛在顶部往下 12%），眼球+脖子+头一起动
- 动作：动作库递归扫描、菜单逐个选、舞蹈收尾与自然站姿待机交叉淡出（`END_FADE`）
- 物理：ammo.wasm，头发/裙摆；收尾不再 reset 物理（避免裙摆瞬移）
- 视觉：三档光照 × 四档滤镜，组合成 5 档"风格"；滤镜走 2D canvas 原生调色
- 菜单：聊天窗口入口、二级页（动作 / 模型 / 配置目录），自动按最长标签算宽度、超窗口自动缩放
- 采集（L1，0 token）：前台窗口分类、全屏、空闲、总体 CPU、媒体（SMTC）、电量
- 本地状态：心情/体力/被戳/跳过几支舞（`~/.nyalume/pet3d_state.json`）
- 控制口：`POST /pet`（dance/say/face/look/style/model/quiet/talk_mode）+ `GET /pet_state`
- 主动搭话（需 `LLM_API_KEY`）：桌宠专属人格、打扰预算、被无视两次静默一小时、
  用户可选安静 / 寡言 / 正常 / 健谈 / 话痨；人格名称取当前模型目录名，
  提示词可包含媒体标题，触发条件包含持续活动 / 体力低 / 电量低 / 空闲
- 打包：公开版（1.2 MB，只带允许二配的 IRIS OUT）+ 自用版（38.7 MB）

## 二、有想法、还没做（backlog）

1. 更多待机/互动动作；**动作骨骼兼容性检查脚本**（报"这支舞用到但模型没有的骨骼"）
2. **把 `pet_*` 注册成 agent 工具**（`tools.py` 里一个装饰器），让 LLM 直接指挥她
3. **状态回传**：主 App 读 `/pet_state`（现在只有她读主 App 的 `/api/activity`）
4. **演化行为**：体力低会喘、被戳多了会躲、好感度阈值触发不同反应
5. **媒体控制**（播放/暂停/上一首/下一首）+ **歌词同步**（歌词来源要另找）
6. 更多触发条件：下载完成、剪贴板高峰期、"今天第一次开机"之类
7. **每模型一份配置**（scale/朝向/表情映射/动作白名单）——换模型最大的坑
8. **运行期换模型**（现在是"重启式"，3–5 秒）
9. 缩放/旋转/当前模型的持久化（现在只存风格、自动降帧、主动搭话档位、手动安静）
10. 双击开聊天窗；走路/跟随光标（聊天窗口已有右键菜单入口）
11. 发布流程（现在只打到 `dist/`，没做上传/更新检查）

## 三、明确舍弃（或者因技术不好实现暂时舍弃，之后或许会加回来）
### 姿势 / 动作
- **抱胸待机**：试用后姿态不自然，回滚；只保留自然站姿
- **手放裙子前面的站姿**：穿模，已回滚
- **趴姿待机**：试用后效果不理想，回滚
- **反应姿势层、捂头、双臂交叉比 ×**：手臂受模型披风/衣物遮挡，穿不过去；回滚骨骼叠加，只留表情和气泡反馈

### 物理 / 手感
- **加粗手臂碰撞体**、**让衣服刚性跟着身体**：更假
- **旋转时暂停物理**：治标
- **抓布料给物理刚体加真冲量**：只做了视觉偏移，真传导没做（还在 backlog）
- **拖拽超过一定距离的回弹**：其实是"帧率不够"的错觉，没做

### 交互玩法
- **戳空反应**（透明判定框）：不需要，砍
- **连击升级 / 抛出惯性 / 贴边偷看**：试过，一般
- **拍照模式**（自拍姿势、存到"人物/自拍"）：先去掉
- **桌宠里内置台词/聊天**（`interactions`）：有 bug 且 OOC，改成"主动搭话"
- **点她时吞掉这次点击**（游戏里不同时触发游戏动作）：会让系统面板点不动，
  而且钩子挡错输入会让整台电脑鼠标键盘失灵 → 永久撤销，钩子一律不吞
- **自动抢/还前台、每 2 秒无条件置顶**：会搅乱全屏游戏的输入/焦点 → 永久撤销

### 视觉
- **144 帧模式**（降分辨率换帧率）：用户明确否掉，分辨率优先
- **菜单里的"换光照""换滤镜"两项**：合并成"换风格"（数据还在，`window.__style(i)` 可手动调）
- **脸红**：只在表情池里闪过一帧，没做专门实现（暂时不管）

### 明确"不建议做"（评估后否掉）
- **视频小窗播放**（把别的窗口画面搬进她的帧里）：要 Windows.Graphics.Capture +
  每帧塞进现有 PNG 管线，DRM/独占全屏还会黑帧；Win11 自带画中画已覆盖
- **让她操作别的应用**（模拟点击/键盘）：风险高，且我们已经踩过输入钩子的坑
- **截图喂模型做视觉监控**：token 杀手（1–2k/张）+ 隐私
- **逐帧/每秒 LLM 驱动骨骼**：延迟与成本都不划算（应是"事件驱动 + 本地插值"）
- **用 LLM 直接生成整支舞蹈 VMD**：质量会崩，只适合程序化小动作（如自制待机）
- **把原始窗口标题/文件名发给云端模型**：窗口只发"类别"（剪辑/游戏/会议）；
  媒体标题会随主动搭话提示词发送，以便谈正在播放的内容

## 四、做不了 / 受限制（不是不想做）

- **胸部物理**：模型没有胸骨，躯干刚体全是静态
- **独占全屏盖不上去**：Windows 限制，游戏得用无边框窗口
- **游戏内互动必须先提权**：反作弊游戏是高完整性进程，UIPI 挡住低完整性的钩子
  （`启动桌宠-管理员.cmd`）
- **游戏内鼠标"移动"拦不住**：游戏直接读 raw input，拦不到
- **IRIS OUT 开头披风上抬**：模型绑定（披风挂在左腕）+ 动作本身，非代码问题
- **模型/动作的商用授权**：锁暝模型禁二配、两份动作禁商用 —— 要商业化必须换素材

## 五、2026-09-21 性能与手感这一轮

### 保留的改动（都带实测数字）

- **帧转换走 C 层**：`_png_to_bgra` 的预乘 + BGRA 换序交给 PIL
  （`convert("RGBa")` → `tobytes("raw","BGRA")`），6.6 → 4.1ms/帧；实测待机
  41.5 → 45.2fps、鼠标高频移动时 33.5 → 41.0fps。输出仍是"预乘 BGRA"，单测钉住。
- **视线换算搬出鼠标钩子**：钩子 / 原始输入那两个每秒上千次的回调只记位置，
  真正的换算放到页面 40ms 一次的 `poll_action`；视线值没变就不过桥；
  删掉右键旋转时每个事件写一行调试日志。
- **布料物理子步按状态走**：待机 1/120（抖动 40.9% → 20.2%），跳舞 1/70
  （同页面同支舞帧数 +18%）。跳舞时布料本来就在动，那点微抖看不出来。
- **眼神幅度收小 + 靠得近才跟**：眼睛 ±0.20 / ±0.17 rad（原 ±0.30 / ±0.26）；
  "靠近"改成按**她的轮廓**外扩自身尺寸 25%（原来是按窗口外扩 35%）——
  窗口比人大得多，光标离挺远她也一直盯着。
- **手指自然弯曲**：`tools/make_idle_vmd.py` 给四指三节 20° / 17° / 11°。
  轴和符号是从 IRIS OUT 等舞蹈里量出来的（左手指骨绕本地 **-Z**、右手 **+Z**，
  舞里的握拳到 80~110°）。拇指不弯：它的轴是 X/Y/Z 混的斜轴，小角度不值得单写。
- **菜单/气泡永远在 UI 顶层**：sprite 加 `renderOrder = 999`。光有
  `depthTest:false` 不够——透明物体之间仍按 z 从远到近排，墨镜这种半透明材质
  比菜单近就会后画、把菜单盖住（火花、洛茜实测）。
- **垃圾物理数据兜底**：质量 > 1e4 的刚体一律改成"跟随骨骼"的静态体
  （希希芙尾巴 2.5e11 → 8 秒不再沉 6.99；菲比 8 根带子 1.7e6 同理）。
- **主模型挑选规则**：目录里混着武器/道具时不再按名字排序取第一个
  （那会让桌宠加载一根"手杖（整.pmx"，看着就像窗口不见了）。规则：先踢道具
  （武器/手杖/道具/锤子/手机/喇叭/泡泡/葡萄/书/杖），再挑名字含角色名的；
  角色名从目录名推（去 `_by_` 与【】前缀，取"—"后、"·"前那段）；
  同名多个取排序第一个（火花那两个 → （修2））。`启动桌宠3D-管理员.cmd`
  的目标已指向火花（修2）。
- **显示窗口被系统收走就重建**：`_reassert` 里先 `IsWindow` 判断，窗口没了就
  重建 + 重新置顶 + 重注册原始鼠标输入。缩放窗口/切全屏之后窗口被系统销毁时，
  以前会变成一个"看不见但一直在跑"的进程，只能去任务管理器结束。
- **调试探针**（页面内，`viewer.html`）：`__probeJitter`（布料抖动 / 是否一直下沉）、
  `__probeLook`（渲染后画面的饱和度 / 亮度 / 对比度）、`matPeek`（材质均值）。
  用法：`viewer.html?...&probe=6000` 或 `&look=3500`，结果写进页面标题。
- **本轮试验中的互动/手感**：摸头时表情停留约 1 秒、短暂看向正面并轻点头，
  手臂保持自然待机；眼神、拖拽、旋转的平滑改按实际帧时长计算。
  `GET /pet_state` 增加显示帧率和帧间隔 p95，便于比较不同模型与动作。
  这几项仍需实机观感验证。
- **菜单命中与显示同坐标**：菜单 Sprite 位于相机前方，点击区域按该深度的
  透视比例计算，避免模型页、风格页点到上方一项。野餐式 MikuQ 的模型尺寸较小，
  旧算法中菜单平面与模型中心的投影比例差约 12%，足以偏出一行；洛茜约 2%。
- **送帧限两帧在途、窗口在消息线程恢复**：用户报告视频式顿挫与窗口消失；
  日志显示送帧积压和窗口连续重建。单帧限流实测约 30fps，现最多允许两帧在途，
  Python 端贴帧忙时丢掉重叠帧；恢复窗口交给原消息线程。待重启后实机验证。
- **撤掉逐进程 CPU 排行采集**：Windows 上 `psutil.process_iter(["name", "cpu_percent"])`
  每次耗时约 1.3–2.2 秒，采集周期与周期性停帧吻合；总体 CPU 数值保留。
  重启后连续日志中不再出现每隔几秒一次的 1–2 秒停帧。

### 这一轮试过并舍弃

- **降分辨率换帧率**：Python 侧放大比省下的解码更贵（7.5 → 11.4ms/帧）
- **帧改用 WebP**：Chromium 里编码 23.6ms，比 PNG 慢 3 倍
- **把 GIL 切换间隔调到 1ms**：无变化
- **`preserveDrawingBuffer: false`**：41.9 vs 41.5fps，无意义
- **复用 DIB / DC**（省掉每帧 CreateDIBSection）：只省 0.25ms/帧
- **物理求解迭代 10 → 25**：抖动 40.9 → 39.9%，帧数还掉；**加阻尼**：无变化
- **看门狗**（推帧停 20 秒就自己退出）：用户否掉——"这种情况让代码判断感觉不太好"
- **拇指弯曲**：轴太斜，小角度不值得
- **在全局鼠标钩子里做视线换算**：每秒上千次回调抢 GIL，越算越卡
- **单帧传输限流实验**：同机锁瞑待机约 49fps，洛茜重启后约 30fps；
  当前改用最多两帧在途，关注帧间隔和观感。
