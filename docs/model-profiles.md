## 怎么使用

当前工作区可直接双击原有 `启动桌宠3D-管理员.cmd`，或以普通权限运行：

```powershell
.\.venv\Scripts\python.exe -m nyalume.frontends.pet.pet3d.pet3d_win
```

正常启动 3D 桌宠，在右键菜单的 **设置与文件** 中翻到 **模型配置（重启生效）**。每份 PMX 首次启动时会创建一份配置，保存在 `~/.nyalume/pet3d_models/`。

文件名是 PMX 绝对路径的摘要，文件内的 `model` 字段标明对应 PMX；同名但不同目录的模型不会互相覆盖。移动 PMX 后会使用一份新配置，可以按 `model` 字段找到旧配置并手动迁移数值。

默认内容：

```json
{
  "scale": 1.0,
  "rotate": 0.0,
  "zoom": 1.0,
  "view_yaw": 0.0,
  "expressions": {},
  "motion_whitelist": null
}
```

| 字段 | 用途 |
|---|---|
| `scale` | 模型空间缩放，0.1–5；沿用原 `--scale` 语义。自动构图会适应模型尺寸，屏幕上想变大请用 `zoom` |
| `rotate` | 模型正面校准，单位度，-360–360；背对屏幕时可试 180 |
| `zoom` | 桌面显示大小，0.45–3；滚轮会自动更新 |
| `view_yaw` | 用户右键旋转的角度，-180–180；叠加在 `rotate` 上，自动更新 |
| `expressions` | 情绪/部位到 PMX morph 名称数组的映射；未指定的沿用现有随机池 |
| `motion_whitelist` | `null` 表示全部动作，`[]` 表示不提供舞蹈；数组项为相对动作库根目录的路径 |

表情例子（只使用模型实际存在的 morph，名称区分字符、大小写和空格）：

```json
{
  "expressions": {
    "happy": ["笑い", "にこり"],
    "sleepy": ["まばたき"],
    "head": ["笑い"],
    "working": ["真面目"]
  },
  "motion_whitelist": ["IRIS OUT_by_pronxy-迫奈熏_3000e43d1f56a24c3bc1c4a6e39a1a4b/IRIS OUT.vmd"]
}
```

请将示例字段合并进已有配置。情绪支持 happy/shy/surprise/angry/sad/sleepy/calm/love；部位支持 head/face/chest/belly/hand/skirt/cloth/leg；working 用于工作中的持续表情。值 `[]` 关闭对应 morph 反馈，不关闭点击本身或气泡。

白名单按完整相对路径匹配，避免不同子目录里的 `Motion.vmd` 串用；菜单、双击、Agent、stdin 和启动参数均沿用筛选结果，自制待机仍是兜底。模型名及动作列表可用 `pet_status` 查看。

视角每秒最多保存一次，静止时不重复写盘；保存使用临时文件和原子替换，运行中只更新 zoom/view_yaw，保留手工修改的其他字段。修改配置后重启生效。突然强制结束进程可能损失最后一秒的调整。

无效 JSON 或越界值会记录错误并回退默认配置，保留原文件以便修正，不用默认值覆盖损坏文件。`/pet_state` 返回 `profile_error`；Agent 的 `pet_status` 只返回配置是否正常，不发送本地配置路径。

显式 `--scale` / `--rotate` 只覆盖本次启动，不写回配置；菜单换模型会移除这两个旧模型的参数，恢复目标模型自己的设置。

## 动作兼容性检查

在项目根目录运行（需要本机 Node.js；复用已经安装的 three，不加新依赖）：

```powershell
node tools/check_motion_compat.mjs "models/野餐式MikuQ/野餐式MikuQ-1.1.pmx" motions
node tools/check_motion_compat.mjs "models/锁瞑/鸣潮_锁暝.pmx" motions --json
```

支持单个 VMD 或递归目录，输出使用的骨骼数、模型缺失的骨骼、其中包含非零位移/旋转的骨骼、缺失的有效表情。镜头/空动作单独标识。

默认缺骨骼只提示；`--strict` 在存在缺失时返回退出码 1，解析失败返回 2。骨骼齐全不保证比例、IK、物理和披风绑定合适；很多配布包含大量静态辅助轨道，不能只按“缺失总数”判断动作质量。检查工具不会自动修改模型、动作或白名单。

本机两套模型的完整检查结果见 [model-compatibility-report.json](model-compatibility-report.json)。个别 VMD 的名称编码会触发 three 解析器警告；本工具与实际渲染器采用相同解码方式，不猜测重命名骨骼。

本次检查的重点：两套模型的 Stay Tonight 均缺 `センター親X`、`センター親Y`、`身じろぎ`、`首かしげ` 的非零轨道；MikuQ 另缺“爱丽丝版だいあるのーと”使用的 `上半身1`。因此优先手工验收这两类动作。其余动作报告中的大量缺失主要是中立轨道，但仍需检查 IK、比例和表情。

## 验证边界

单元测试覆盖配置隔离、无效输入、损坏文件保留、白名单与同名动作、切换模型参数和实际 VMD 解析。浏览器测试使用真实 PMX/贴图/待机动作，验证显示、表情映射、缩放/旋转写盘和重载恢复；锁暝测试启用 Ammo 物理。

测试不安装全局鼠标钩子，不启动另一个原生桌宠去抢占当前实例。Windows 分层窗口、游戏内高权限输入和两进程换模交接仍属于人工验收范围。

## 头部抽动修复（2026-09-23）

视线与点头现于动画/IK 之后、物理解算之前执行，并同步世界矩阵，避免头部已转动而头发碰撞体仍使用旧姿态。切舞在新姿态写入后对齐一次刚体并清除旧速度，删除延迟关开物理及集中预热；自然收尾继续保留物理状态，姿态交叉淡出在解算前准备。舞蹈沿用待机的 1/120 秒物理子步，最多六步覆盖已有 50ms 帧时间上限，物理计算量可能高于原舞蹈档。

真实锁暝 PMX、Ammo 与 IRIS OUT 回归覆盖视线换向、舞蹈、自然收尾及手动返回待机；检查头颈姿态和世界矩阵与同帧物理输入一致，切舞只重置一次、自然收尾不重置。相关 52 项测试通过。此验证消除了已复现的更新顺序冲突，不代表所有模型的重叠碰撞体或动作绑定问题都已消除。重启 v2 桌宠加载修改。
