# 3D 桌宠：待验证猜测（2026-09-21）

> 只是猜测，不是结论。每条都写了"怎么验"。改动摘要见
> `docs/pet3d-想法与舍弃清单.md` 第五节。

## 一、"灰蒙蒙 / 塑料感"

### 猜测 1（主）：是光照 + 缺描边，不是单个模型的材质

- 依据 A：viewer 里**没有 OutlineEffect / EffectComposer**。MMDLoader 只把描边参数
  挂在 `userData.outlineParameters` 上，真正画那条黑描边要 OutlineEffect。所以
  所有模型都没有 MMD 的边线，浅色角色在大面积平光下就是"塑料模特"味。
  这也解释"怎么布伦妮、火花也灰了"——共因，不是各自材质坏了。
- 依据 B：光照是加法（环境光 0.6~1.0 + 材质自发光）。加白光会同时抬高 R/G/B，
  饱和度被稀释。实测洛茜渲染后的不透明像素：**平均饱和度 0.091**，
  而它贴图本身是 0.30 —— 掉到三分之一，是光照/叠加洗白的。
- 验法：用 `__probeLook` 量各模型在同一档光照下的 sat/lum/p10..p90，
  再把环境光压下来、主光/补光按比例加上去，看 sat 能不能追平锁瞑；
  以及接上 OutlineEffect 再量一次。
- 顺带：光照档里"原版（平光）"是 `ambient 1.0`，最平最洗；在这一档下比较，
  什么模型都会显灰。

### 猜测 2：洛茜自身材质偏平（量到的唯一异类）

- 洛茜整套平均 diffuse **0.87** / ambient **0.66**，其余模型一律 1.00 / 0.50；
  且它是**唯一完全没有自带 toon 贴图**的模型（15 个材质全走 three 内置坡道）。
- 已做的"材质归一"把整套拉到 1.00 / 0.100（探针 `mat=[15个 d=1.00 ae=0.100]`），
  但用户反馈仍然灰 → 说明它主要还是被猜测 1 的共因压着。

### 猜测 3：我加的"材质归一"可能帮倒忙

- 归一按**整套材质的平均值**缩放，平均值里会混进很暗的材质（黑发、深色衣服），
  这类模型平均被拉低 → 又把整体提亮 → 更灰。布伦妮（13 个描边材质）、
  火花（20 个）正好是这种。
- 验法：量这两个模型的 `mat=` 探针值，如果平均 diffuse 明显 > 1.00 或
  emissive 明显 > 0.100，就坐实了；改法是用中位数或排除极暗材质。

## 二、跳舞卡顿

- 实测（千夏，IRIS OUT，真机）：待机 fps 中位 **58.9**、跳舞 **55.7**，
  `gap_p95` 约 20ms。该场景的平均帧率不足以解释全部观感问题；
  偶发低帧仍需定位，不能只凭这组数据归因于物理。
- **已排除「three 只做线性插值」**：当前安装的 `three@0.171.0` 的
  `node_modules/three/examples/jsm/loaders/MMDLoader.js` 在
  `buildSkeletalAnimation` 中读取 VMD 的插值参数，`_createTrack` 为轨道设置
  `CubicBezierInterpolation`，旋转还用四元数 slerp。不能靠改 `smooth` 补上
  本来就已存在的贝塞尔插值；贸然改会改变原动作的速度曲线。
- 接下来要验的是具体模型和动作上的**帧间隔尖峰、物理解算、动作素材本身**。
  对同一模型同一支舞分别开/关物理，记录 `display_fps`、
  `frame_gap_p95_ms` 和观感，再决定是否动动作链路。
- 2026-09-21 晚上用户报告的是类似视频播放时一顿一顿、随后窗口消失。
  日志出现解码 90–174ms、`gap_p95` 100–300ms 的尖峰，并在恢复后出现
  不合理的瞬时高帧数；这指向送帧请求积压。19:42:28 起窗口连续被重建，
  已确认重建曾从送帧线程发起，窗口随该线程结束而再次消失。
  源码把窗口重建移回消息线程，重启后连续消失已停止。单帧在途时洛茜只有约
  30fps，因此现在改为最多两帧在途，Python 端并发到达时丢弃旧帧；待实机验证。
- 周期性停帧另有独立原因：桌面采集每 5 秒读取一次所有进程的 CPU 百分比，
  单独计时 `psutil.process_iter(["name", "cpu_percent"])` 约 1.3–2.2 秒，
  与新进程日志里的周期性停顿吻合。已去掉这项排行采集，保留总体 CPU；
  重启后的连续日志不再出现每隔几秒一次的 1–2 秒停帧；实际观感仍需用户确认。

## 三、后续验证顺序

1. 固定模型、动作、窗口尺寸与光照档，比较舞蹈时物理开/关的
   `display_fps`、`frame_gap_p95_ms` 和实际观感；同时检查动作素材本身。
2. 用 `__probeLook` 对比同一模型的光照设置，再决定是否调整环境光与主光比例。
3. 在相同条件下试接 OutlineEffect，比较描边效果和帧率。
4. 量化布伦妮、火花的材质归一结果；若归一导致过亮，再改算法或撤掉。
